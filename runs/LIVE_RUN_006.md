## What the report describes

A recurring three-stage workflow the director already runs by hand against real repositories:

1. **Hunt** — sweep an existing codebase for improvements across several lenses at once:
   code-level, architectural, UI/UX, and "make things work" (correctness).
2. **Externalize** — write each finding as an issue on the repository's tracker.
3. **Drain** — implement the issues one by one, each pickup starting from the issue text alone.

## The gap analysis (executed against the suite at this revision)

The hunt stage is owned: `latent-audit`, `structure-gate`, `senior-review`, `threat-model`,
`data-tier` own the no-symptom lenses; `symptom-audit` owns the felt-complaint lens (its
cohesion/UX sweep covers the director's "ui and ux"). §8.2 makes the multi-lens fan-out legal as
parallel isolated gates.

The externalize and drain stages were unowned. **(proven)** — executed this session, zero hits:

```
grep -rniE "issue tracker|github issue|backlog|gh issue" skills/ PROTOCOL.md MAP.md
```

No skill, no PROTOCOL section, and no MAP entry mentioned an issue tracker, a backlog, or the
act of closing externalized work with evidence. Findings landed in ledger files and stopped
there; the director was hand-carrying them to the tracker, and nothing governed what an issue
must contain for a future session to implement it alone (Law 2, artifacts outlive conversations)
or what a close must prove.
